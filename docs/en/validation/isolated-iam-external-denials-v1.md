# Isolated IAM External Enforcement — Infrastructure V1

**Status: RUNTIME IMPLEMENTATION CANDIDATE — NOT YET EXECUTED / VERIFIED on merged main.**

This is the first *runtime* increment after [experiment-contract V1](../architecture/isolated-enterprise-iam-bypass-proof-v1.md). It focuses only on the **external enforcement** side of three frozen negative cases, not on all eight contract cases.

## What is exercised

1. `DENY_04`: a reachable mTLS client signed by the run-local CA, but with `unscoped-probe` identity, receives HTTP **403** from the synthetic IAM API. The independent target-owned SQLite audit must record that refusal.
2. `DENY_03`: a reachable client without a certificate is refused by the target TLS handshake. A random connection error is insufficient: the same target must first have answered the scoped-negative HTTP 403.
3. `DENY_02`: an agent-only container attempts TCP to the target's **observed actual IP**, not merely an unresolved DNS name. That route must fail; resolved Docker Compose and runtime container topology must independently show disjoint networks.

The target refuses all effects in this phase (`LAB_ALLOW_MUTATIONS=0`); **there is no allowed execution case yet**. The authorization chain, approval, single-use consumption, positive mutation and read-only reconciliation remain follow-up work.

## Run

With Docker Engine + Compose v2, Python 3.12+, Bash and OpenSSL installed:

```bash
python3 -m pytest -q tests/quality/test_isolated_iam_external_denials_v1.py
bash scripts/enterprise_iam_lab/run_infra.sh
```

The script creates a disposable private CA and a target server certificate, then a deliberately insufficient-scope client certificate. Only the target container sees the server key, and only the unscoped probe sees its client key; the agent receives **no certificates or keys**. Credentials are never uploaded. The compose networks are both internal; the target has **no published host port**. The service and probe processes are unprivileged and have no Docker socket volume.

**Evidence trust boundary:** Evidence is generated by a GitHub-hosted test runner and an independent *process* within the same Docker daemon. This proves no independent host or cloud-infrastructure administration boundary. Host root and Docker socket compromise are out of scope. The artifacts are not signed provider attestations.

The report must read **`INFRA_DENIALS_ONLY_NOT_FULL_VERITAS_PROOF`**, not `PROVEN`; it explicitly lists five unexecuted contract cases. Merging the PR is not a completed customer deployment, nor an IAM product certification.
